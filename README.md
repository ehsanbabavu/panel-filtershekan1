# فیلترشکن | پنل مدیریت

پنل مدیریت فارسی، راست‌چین و واکنش‌گرا با React و TypeScript در کلاینت و Express در سرور.

## اجرا

```bash
npm install
npm run dev
```

وب‌اپ در `http://localhost:5173` و API در `http://localhost:3001` اجرا می‌شود.

## ورود پیش‌فرض

- نام کاربری: `ehsan`
- رمز عبور: `232111Eee@`

برای تغییر اعتبار ورود، مقادیر `ADMIN_USERNAME` و `ADMIN_PASSWORD` را در محیط اجرا تنظیم کنید. نمونهٔ متغیرها در `.env.example` آمده است.

## PostgreSQL

سرور برای اجرا به PostgreSQL نیاز دارد. مقدار `DATABASE_URL` را در محیط اجرا تنظیم کنید؛ سرور در اولین راه‌اندازی جدول‌های مدیران، نشست‌ها، کاربران و پیام‌های چت را می‌سازد و کاربران نمونه را اضافه می‌کند. رمز عبور مدیر هنگام ساخت اولیه ذخیره می‌شود. برای دیتابیس‌های ابری که TLS نیاز دارند، `DATABASE_SSL=true` تنظیم کنید. در Vercel مقدارهای `DATABASE_URL` و در صورت نیاز `DATABASE_SSL` را در Project Settings → Environment Variables وارد کنید.

## بخش‌ها

- داشبورد با آمار، نمودار و فهرست کاربران اخیر
- فهرست و جست‌وجوی کاربران
- صفحهٔ اشتراک‌ها
- گفت‌وگوی پشتیبانی

ورود از API سمت سرور بررسی می‌شود و مسیرهای API پس از ورود به توکن نشست نیاز دارند. مدیر، نشست‌ها، کاربران و پیام‌های چت در PostgreSQL نگهداری می‌شوند. داده‌های اشتراک و آمار داشبورد فعلاً نمونه‌ای هستند.

## آپلود گروهی ساکس‌ها

در بخش «ساکس»، دکمهٔ «آپلود فایل TXT» را بزنید. هر خط فایل باید به‌ترتیب شامل IP یا میزبان، پورت، نام کاربری و رمز عبور با جداکنندهٔ `:` باشد:

```text
203.0.113.10:80:example-user-1:example-password
203.0.113.11:1080:example-user-2:example-password
```

ساکس‌ها فعال و به‌ترتیب خط‌های فایل به انتهای فهرست اضافه می‌شوند؛ رکوردهای قبلی و مشخصاتشان حفظ می‌شوند. نام‌ها به‌صورت «ساکس 1»، «ساکس 2» و ادامهٔ شماره‌های موجود ساخته می‌شوند. فایل‌های بعدی هم رکورد تازه اضافه می‌کنند. خط‌های خالی نادیده گرفته می‌شوند؛ فایل تا ۱ مگابایت و ۱۰٬۰۰۰ ساکس پشتیبانی می‌شود. اگر خطی نامعتبر باشد، شمارهٔ خط نمایش داده می‌شود و هیچ بخشی از فایل ذخیره نمی‌شود.

مسیر مدیر: `POST /api/proxies/import` با توکن نشست و بدنهٔ JSON به‌شکل `{"content":"متن فایل"}`. بررسی و ذخیرهٔ گروهی در Express و Vercel مشترک است و همهٔ رکوردهای یک فایل در یک تراکنش PostgreSQL ذخیره می‌شوند.

کنار هر ساکس یک کادر انتخاب و در سرستون گزینهٔ انتخاب همه قرار دارد. بعد از انتخاب، با دکمه‌های گروهی می‌توانید ساکس‌های انتخاب‌شده را فعال، غیرفعال یا پس از تأیید حذف کنید. سایر رکوردها و ترتیب فهرست حفظ می‌شوند. مسیر `PATCH /api/proxies/bulk` بدنهٔ `{"ids":["1","2"],"active":false}` و مسیر `DELETE /api/proxies/bulk` بدنهٔ `{"ids":["1","2"]}` می‌گیرد. هر دو مسیر به نشست مدیر نیاز دارند. مسیرهای تو در تو برای Vercel فایل API صریح دارند.

## وضعیت اتصال کاربران

وضعیت کاربران بر اساس اتصال VPN اپ موبایل محاسبه می‌شود. ورود یا ثبت‌نام به‌تنهایی کاربر را آنلاین نمی‌کند. اپ پس از اتصال، هر ۲۵ ثانیه گزارش اتصال می‌فرستد و در قطع اتصال، خطا یا لغو مجوز VPN گزارش آفلاین ارسال می‌کند. این گزارش در سرویس بومی اندروید اجرا می‌شود تا به باز ماندن صفحهٔ اپ وابسته نباشد.

فهرست کاربران پنل هر ۱۰ ثانیه تازه می‌شود. اگر گزارش اتصال بیش از ۹۰ ثانیه نرسد، وضعیت آفلاین می‌شود؛ این حالت بسته شدن ناگهانی اپ، خاموش شدن گوشی و قطع اینترنت را هم پوشش می‌دهد. اگر یک حساب روی چند دستگاه متصل باشد، تا قطع آخرین دستگاه آنلاین است. تغییر وضعیت در فرم مدیر خودکار است.

مسیر گزارش: `POST /api/mobile?action=presence` یا `POST /api/mobile/presence`، با توکن نشست اپ در `Authorization: Bearer <token>` و بدنهٔ `{"connected":true,"sequence":1}`. شمارهٔ گزارش باید افزایشی باشد و در دستگاه ذخیره شود؛ گزارش دیررس نمی‌تواند قطع اتصال جدیدتر را بازنویسی کند. اپ‌های قبلی که گزارش VPN نمی‌فرستند آفلاین نمایش داده می‌شوند و باید به نسخهٔ جدید ارتقا یابند.

مهاجرت جدول‌ها هنگام اولین درخواست اجرا می‌شود و حساب‌ها و نشست‌های ورود قبلی حفظ می‌شوند. متغیر محیطی تازه‌ای لازم نیست.

`npm test` مسیرهای ورود، اتصال، قطع، چند دستگاه، پایان مهلت گزارش، گزارش دیررس و مهاجرت را با اجرای SQL واقعی PostgreSQL در PGlite بررسی می‌کند. بارگذاری نسخهٔ JavaScript توابع API با اجرای مستقیم Node نیز آزموده می‌شود. `npm run build` مسیرهای ماژول سرور را با قواعد NodeNext بررسی می‌کند تا خطای بارگذاری در Vercel پیش از انتشار مشخص شود.
